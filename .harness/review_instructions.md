# 독립 리뷰 역할 계약

이 문서는 명시적으로 실행하는 `run_harness.py review`의 검수 절차다. 설치·진단·프로젝트 연결은 리뷰를 시작하지 않는다. Sol/Terra 반복 리뷰는 별도의 `loop` 모드가 관리한다. 프로젝트에 INTERVIEW.md·FUNCTIONAL_SPEC.md·PLAN.md·HANDOFF.md가 있으면 참고하고 PLAN.md에 문서 매핑이 있으면 따른다. 누락된 문서는 검토 한계로 기록한다. 별도 프로필이나 고정 모델을 요구하지 않는다.

| 역할 | 할 일 | 완료 조건 |
|---|---|---|
| 메인 Codex | 핵심 구현·테스트·독립 검산 완료와 수정·제출 시간 여유를 판단 | 수행 또는 생략 사유 기록; 시간 부족이면 실행 확인·제출 준비 우선 |
| 메인 Codex (리뷰 선택 시) | 별도 리뷰 최대 1회 호출 | 실제 실행 기록과 검토 대상이 연결됨 |
| 독립 리뷰어 | 요구·현재 코드·테스트·주변 호출자·예외 경로 검토 | 근거 있는 지적 또는 0건, 미확인 범위 반환 |
| 메인 Codex | 지적 재현·판단·수정·기각 이유 기록, 관련 재검증 | 차단 지적 해결, 남은 위험 기록, 최신 검증 확인 |

## 실행

`python .harness/harness.py review "대상·요구·판정 기준" --timeout 300 --remaining-seconds 1500 --reserve-seconds 1200`은 `.codex/agents/kty-reviewer.toml`과 이 파일의 지침을 읽어 새 `codex exec` 프로세스에 전달한다. 숫자는 예시이며 실제 시계·마감·측정한 검사 소요 시간으로 계산한다. 예약 시간은 수정·관련 테스트·최종 검증·제출 준비를 모두 포함한다. `remaining-seconds < timeout + reserve-seconds`이면 모델을 호출하지 않고 생략한다. `resume`·`fork`를 쓰지 않으며 메인 대화 이력을 전달하지 않는다. 읽기 전용 샌드박스에서 실행하고 결과는 부모 실행기가 `.harness/work/`에 저장한다. 역할 TOML의 자동 등록 여부에 의존하지 않는다.

독립 코드 리뷰는 선택 사항이다. 3시간 과제에서도 핵심 구현·테스트·독립 검산을 마쳤고, 리뷰 뒤 수정·관련 재검증·최종 실행 확인·제출 준비 시간까지 확보된 경우만 최대 한 번 호출한다. 조건 미충족·시간 부족·남은 시간 미확인이면 별도 승인 없이 생략 사유를 PLAN.md에 기록하고 실행 확인·제출 준비를 우선한다. 리뷰 생략 자체는 완료·제출 준비를 막지 않으며, 실제 미완성 요구·실패한 검사·알려진 미해결 결함은 계속 보고한다.

수행할 때는 PLAN.md와 기존 리뷰 실행 기록을 확인하고 시작 기록을 남긴다. 기능별 검증·수정·최종 검증·마무리·세션 재개에서는 새 리뷰를 자동 시작하지 않는다. 생략한 리뷰를 마무리 단계에서 의무적으로 보충하지 않는다. 실패·시간 초과도 자동 반복하지 않고 미검증으로 보고한다. 실행기는 프로젝트별 `.harness/work/independent-review-claim` 디렉터리를 원자적으로 생성해 동시 호출도 최대 한 번만 실행한다. 실패한 호출도 한 번에 포함한다. 이 기록이나 과거 리뷰를 지워 재시도하지 않는다. 사용자가 이후 추가 리뷰를 명시적으로 요청하면 별도 변경 요청으로 기록하며, 이 실행기에는 자동 재시도나 횟수 우회 옵션이 없다.

CLI 외의 독립 에이전트로 이미 리뷰했다면 PLAN.md 결과 블록에 실행 여부·근거·지적 처리를 기록하고 CLI 리뷰를 추가 호출하지 않는다. CLI는 외부 에이전트의 실행 여부까지 자동 판별하지 못한다. 핵심 기능·테스트 준비 여부와 예약 시간의 충분성은 메인이 판단한다. 종료 코드 0은 유효 리뷰 완료, 2는 유효 리뷰의 HIGH/CRITICAL 지적 존재, 1은 실행·결과 오류, 3은 시간 부족 또는 이미 시도하여 미실행, 130은 사용자 중단이다. 3을 리뷰 성공으로 기록하지 않는다.

메인과 리뷰어는 같은 파일을 보므로 리뷰 중에는 대상 파일 편집을 멈춘다. 시작·종료 지문이 다르면 유효한 리뷰로 처리하지 않는다. 리뷰어에게 이전 리뷰 결론을 정답으로 주지 않는다. 다만 요구사항과 실제 결정은 현재 문서에서 읽게 한다.

## 반환과 처리

- 지적 필드: `severity`(CRITICAL/HIGH/MEDIUM/LOW), `file`, `line`, `input`, `evidence`.
- `input`에 구체적 입력·상태와 실패 결과를, `evidence`에 요구·테스트·실제 호출 경로 근거를 적는다.
- 근거 없는 스타일 지적은 만들지 않는다. 지적 0건도 유효하다. 실행하지 못한 테스트나 읽지 못한 범위는 `limitations`에 적는다.
- 메인은 각 지적을 검증하고 PLAN.md에 수용·수정·기각 이유와 재검증 명령·결과를 남긴다. 심각도만 보고 자동 수정하거나 자동 기각하지 않는다.
- CRITICAL·HIGH는 해결 전 완료로 표시하지 않는다. 리뷰 호출 성공, 코드 오류 없음, 테스트 통과, 실제 제출 완료는 각각 다른 사실이다.
- 독립 검산은 구현과 별개인 기준값·손 계산·원본 집계로 계속 수행한다. 코드 리뷰가 이를 대체하지 않는다.

## 공통 점수와 자동 기록

.harness/review_criteria.json의 공통 20개 기준을 의도·인지·기술·정직성·소통의 다섯 축으로 평가한다. criterion_scores에는 각 기준 ID를 정확히 한 번씩 넣고 status, reason, evidence_refs를 반환한다. 상태는 PASS/PARTIAL/FAIL/UNVERIFIED/NA이며 점수는 실행기가 계산한다. 실행하지 않은 기준은 UNVERIFIED로 남기고, NA는 실행기가 사전에 적용 제외를 허용한 기준만 사용할 수 있다.

직접 읽은 파일은 file:프로젝트상대경로로 참조하고 reviewed_files에도 포함한다. 이번 리뷰에서 실행한 명령은 command:정확한 셸 명령 문자열로 참조한다. 실행기는 현재 파일 해시와 실제 완료된 CLI 실행 이벤트를 대조한다. 파일 읽기는 실행 증거를 대신하지 않으며, 없는 증거·중복 기준·위조된 점수 구조는 미산정으로 기록한다.

근거는 해당 기준을 실제로 확인해야 한다. 일반 단위 테스트의 성공을 새 세션에서 문서만 읽고 작업을 이어가는 HAND02 검증으로 인정하지 않는다. 새 세션·다른 환경에서 실행하지 못한 항목은 UNVERIFIED로 남기고 사람의 이해·수용 여부를 추정해 확정하지 않는다. 비밀정보를 발견한 경우 실제 값을 응답이나 보고서에 복사하지 말고 위치·항목·노출 상태만 기록한다.

실행기는 실제 검증 결과·미실행 검사·리뷰 결과를 docs/progress.md와 docs/review-score.md에 기록한다. 두 문서는 실행기만 수정한다. 새 검증은 리뷰를 다시 호출하거나 점수를 다시 매기지 않는다. 소스가 바뀌면 기존 리뷰 점수는 이전 소스의 기록으로 표시하며, 문서 갱신만으로 검증 통과 기록을 최신 상태로 바꾸지 않는다. 점수는 기존 기능 검증과 별개이며 추가 최소 점수 기준은 없다.

리뷰 후 수정은 메인이 관련 테스트·독립 검산으로 반드시 확인하며 새 독립 리뷰를 받은 것으로 기록하지 않는다. 이후 최종 검증과 제출 확인을 수행한다. 남은 불확실성·미구현 Must·미해결 지적은 그대로 남긴다. 자동 완료 감사나 리뷰 강제 훅은 설치하지 않는다.
